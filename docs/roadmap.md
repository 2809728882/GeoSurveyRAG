# 完善路线图

这份路线图用于把 GeoSurveyRAG 持续升级为更接近生产环境的 LLM 应用。

## 1. 知识库自动更新

当前已支持：

- 文档哈希 manifest。
- 检测 `data/knowledge` 文档新增、删除、修改。
- `/admin/index/rebuild` 手动触发重建。
- `index_updater` 轮询式自动更新进程。

下一步可增强：

- 接入 GitHub Actions：知识库变更后自动构建索引并发布 Docker 镜像。
- 接入对象存储或网盘目录：同步测绘规范、验收报告、元数据说明。
- 增加增量索引：只重建变化文档，降低大知识库更新时间。

## 2. 向量数据库生产化

当前使用 JSON 向量索引，方便演示和离线运行。生产环境建议：

- 小规模：FAISS，本地部署简单，查询快。
- 中大型：Milvus 或 Qdrant，支持集合管理、过滤条件和横向扩展。
- 企业搜索融合：Elasticsearch/OpenSearch，便于 BM25 + dense vector 混合检索。

## 3. Agent 工具增强

建议继续添加：

- PostGIS 空间相交、缓冲区、包含关系查询。
- ArcGIS REST / GeoServer WFS 图层查询。
- 坐标系统自动识别和批量坐标转换。
- RINEX/GNSS 文件解析工具。
- DOM/DSM/点云质量检查报告解析工具。

## 4. 评测体系增强

建议从关键词命中升级为多指标评测：

- 检索命中率、MRR、Recall@K。
- 答案忠实度和引用正确率。
- 工具调用准确率。
- 人工标注集和错误案例库。
- Prompt 版本对比和线上 A/B 实验。

## 5. 运维与成本控制

上线前建议补齐：

- 结构化日志和 trace id。
- 请求耗时、Token 用量、工具调用成功率统计。
- 用户权限、数据脱敏和审计留痕。
- 缓存常见问题，降低模型调用成本。
- Docker 多阶段构建和镜像体积优化。

## 6. 后续优先级

已完成：

1. 增加 FAISS 可选向量后端。
2. 增加 WebGIS 前端页面。
3. 扩展 30+ 条测绘问答评测集并支持 Markdown 评测报告。
4. 增加手动入库和爬虫自动更新双通道。

下一阶段优先：

1. 接入 Milvus/Qdrant 容器服务。
2. 使用真实 Embedding 模型替换哈希向量。
3. 接入 PostGIS 或 ArcGIS REST，做真实图层查询。
